# Site structure

This is a **single-page portfolio**. No separate project pages at launch.

Recommended order:

1. Hero
2. Work
3. Services
4. How it works
5. Testimonials
6. About
7. FAQ
8. Contact
9. Footer

## Navbar

Minimal navigation only:

- `kq` on the left
- Work
- Services
- About
- Contact

Behavior:

- sticky/fixed
- hides while scrolling down
- returns when scrolling up
- transparent/dark at top
- may gain a subtle surface/background once content moves underneath it
- mobile gets a compact menu, not a desktop nav squeezed into one line

If `projects` is empty, hide Work from both page and nav. If `testimonials` is empty, hide Testimonials completely.

## Hero

Full viewport on desktop.

The first screen must make these things obvious without reading a paragraph:

- `kq`
- Roblox scripter
- builds full systems / takes scripting work
- available to hire

No system videos in the hero.

Hero should be typography-led with abstract motion/background details.

## Work

Compact project/system cards. No giant case-study pages for small systems.

Each completed system can have:

- thumbnail / poster
- click-to-play recorded demo
- title
- one-line description
- a few useful technical details
- `My work`
- `Provided assets` when relevant

Do not publish unfinished work or “coming soon” cards.

## Services

A clear section called something like `What you can hire me for`.

It should list scripting work without looking like a Fiverr menu.

Suggested grouping:

### Systems
- Full systems
- Inventories
- Round systems
- Procedural systems

### Backend / game logic
- Data saving
- Matchmaking
- Admin systems
- Anti-exploit

### Integration / feature work
- UI logic / wiring
- Shops / monetization
- Bug fixes / small tasks
- General Roblox scripting

### Performance
- Optimization

The exact layout can change, but the visitor should quickly understand that small jobs and full systems are both welcome.

## How it works

Keep this short:

1. Client sends what they need.
2. Scope, payment, timeline, and provided assets are agreed.
3. kq builds it.
4. Client tests it.
5. Fixes / changes follow whatever was agreed for that job.

Do not turn this into a fake “five-step methodology”. It is just there to remove uncertainty.

## Testimonials

One dedicated section.

Use real quotes only. Real username / role / project can be shown when permission exists.

If a quote is directly tied to a project, a small version may also appear near that project card, but the main testimonials live in one section.

## About

Short. No life story.

Explain:

- kq is a Roblox scripter based in Romania
- about 1.5 years scripting
- full systems + smaller scripting tasks
- can work from a spec or help define system logic
- scripting only; visual/audio asset creation is not sold as a service

## FAQ

Keep it around 4–6 questions.

## Contact

Direct contact only.

Primary CTA: Discord `@kqrara` with copy button.

Secondary CTA: Telegram direct link.

Show payment methods nearby.
